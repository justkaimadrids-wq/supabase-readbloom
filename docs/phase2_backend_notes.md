# Phase 2 Backend Notes

## What Phase 2 Adds

Phase 2 establishes the backend source of truth for ReadBloom:

- Supabase Auth-backed profile model.
- Role-specific student, teacher, and admin access boundaries.
- Grade/section relationships.
- Teacher-created books and quiz questions.
- Student reading submissions.
- Transcript and word-alignment storage.
- Teacher feedback and student messages.
- Badge catalog and awarded badges.
- Safety agreement versioning.
- Activity logs.
- Private media storage buckets.

## Important Design Decisions

### Profiles Reference `auth.users`

Every application account has:

- one Supabase Auth user,
- one `profiles` row,
- optionally one role-specific row in `student_profiles` or `teacher_profiles`.

The `profiles.role` value is used by RLS helper functions. Flutter apps should still perform a client-side role check after login for UX, but security must come from RLS.

### Books and Passages Are Snapshotted on Submission

`reading_submissions` stores:

- `book_title_snapshot`
- `passage_text_snapshot`

This prevents old submissions from changing if a teacher later edits the source book.

### Speech-to-Text Results Are Separate

`transcript_results` is separate from `reading_submissions` because transcription is asynchronous and can fail. The teacher UI should support:

- uploaded but not processed,
- processing,
- processed,
- failed.

### Videos Are Private

Reading videos and audio should not be public. Teachers should view recordings only after authorization checks, ideally through signed URLs generated by a future Edge Function.
